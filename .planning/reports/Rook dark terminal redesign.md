# Give Rook depth without losing darkness

**Execution authorized; demo implementation and verification recorded in the [implementation receipt](Rook%20dark%20terminal%20implementation.md).** Rook needs a near-black canvas, clearly bounded foreground instruments, and selective violet illumination—not another global increase in brightness. The last global-lightening pass has been rolled back and rebuilt; the redesign started from that restored dark demo. All old design-token values and restrictions are superseded by the user's explicit instruction; this proposal defines a fresh hierarchy rather than preserving indiscriminate violet or banning violet surfaces. Keep Manrope, readable numerals, the removed price ribbon, concise product language, and every meaningful analytical interaction. Prove the direction on **Exposure at 1440×900 and 1920×1080**, then propagate it across the other six views. The demo supplies the first visual proof; the shared research also guides the actual frontend GSD phases without copying demo code or repeating research. Neither this plan nor specification updates complete AXF-01 or AXM-04.

## Dark instruments need hierarchy before decoration

The source audit finds five close neutral surfaces, flat panel faces, repeated explanatory blocks, and several competing summaries. Exposure repeats worst-case readings across diagnosis, metrics, downside ranking, and stress monitoring. Portfolio repeats grouping context; Trade stacks several introductory headings before the decision. The main scenario chart is a 512×140 SVG rendered only 70px high. Relationships can show 16px node titles at 85% scale, making their visible size 13.6px; explicit Fit can shrink them much further. **A palette swap alone cannot solve these problems.** Reduce repetition, promote the primary visual, then use light to distinguish that visual from its surroundings. ([Code audit](../research_notes/Rook%20dark%20terminal%20redesign/code-audit.md), [ExposureView.tsx](../../demo/src/components/ExposureView.tsx), [OutcomeChart.tsx](../../demo/src/components/OutcomeChart.tsx), [RelationshipGraph.tsx](../../demo/src/components/RelationshipGraph.tsx))

The proposed foreground language has four levels: a near-black structural canvas, bounded neutral panels, raised controls and selections, and one illuminated focal surface per decision screen. Most table bodies remain neutral. Readable secondary text stays readable; hierarchy comes from grouping, size, weight, spacing, and fewer sentences rather than faint labels. Gradients add depth only where they make the next reading or action easier to locate.

## Fresh surface roles make gradients intentional

These values are **candidate implementation recipes, not sampled reference tokens or verified rendered results**. Keep the existing Rook brand. Violet communicates focus and selection; green/red carry signed P&L, and amber carries attention. The system needs no new theme engine, chart library, blur treatment, or animation framework.

| Role | Candidate value and intended use |
|---|---|
| Canvas / chrome | `#08090D` page, `#101116` top bar. Preserve dark gutters between instruments. |
| Panel / raised control | `#171820` neutral panels; `#20212B` raised inputs, selected neutral tabs and controls. Recessed data wells use `#0E0F14`. |
| Edges | Subtle panel separator `#3B3D4C` plus a restrained top inset light. Essential control boundaries and keyboard focus use stronger measured contrast; subtle decorative edges do not substitute for those. |
| Feature surface | `radial-gradient(ellipse at 86% 0%, rgba(124,92,245,.22), transparent 62%), linear-gradient(130deg,#1B1729 0%,#171820 48%,#101116 100%)`. Opaque base; light fades before dense rows. |
| Selected object | `linear-gradient(125deg,rgba(124,92,245,.18),rgba(124,92,245,.04) 65%),#1B1A24`; restrained violet edge. For one selected card/node, not all objects. |
| Primary action | `linear-gradient(135deg,#7052EF,#6044D8)` with near-white text; verify the brightest stop and hover state. No scale-on-hover or luminous text. |
| Text | Primary `#F5F5FA`, secondary `#C4C5D0`, metadata `#9698AA`. Signed values also carry signs/labels. |
| Geometry / typography | 10px panels, 6px controls, 4px badges; 16–20px panel padding. Manrope with tabular numerals. Data/body 14–15px; secondary labels 13px; 12px only for genuinely tertiary metadata. Section headings 18–22px; screen title 26px; lead metrics 32–36px. |

The flat neutral roles have calculated WCAG relative luminances of approximately **0.0028 canvas, 0.0057 chrome, 0.0094 panel, and 0.0157 raised**. These numbers describe the proposed separation, not a mandatory ratio between every surface. Metadata `#9698AA` over flat `#20212B` calculates to approximately **5.61:1**. Rendered gradients require separate sampling at the brightest region beneath each label: target **4.5:1 normal text, 3:1 large text, and 3:1 essential controls and graphical distinctions**. Do not assume a readable token guarantees readable composited content. ([WCAG contrast minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html))

Use the feature gradient on Exposure's headline instrument and Trade's selected decision surface. Edge lighting can subtly separate the shell and panel headers. Actual charts can use a crisp line or selected bar with translucent fill toward a neutral baseline; preserve heatmap P&L colors. Graph selections can have a bounded violet face and edge, while other nodes stay opaque and readable. Tables, evidence paragraphs, and ordinary inputs receive no atmospheric glow. **One dominant illuminated surface per view** is the default, with small selected states subordinate to it. All gradients remain static; no pulsing halos, animated numbers, mouse-tracking spotlights, or moving background lights.

## Lighting correction after the rendered proof (2026-10-07)

The user rejected straight vertical component/header gradients as bevelled and dated. The active visual direction is **composition-wide radial illumination**: an off-center violet source and a wider neutral light field continue through adjacent translucent panels and gutters. Position, radius and falloff define depth; do not assign the same gradient independently to every component. Panel headers remain transparent, data wells remain opaque, and selected controls may use a smaller radial source. The neutral gray itself must vary with the shared light rather than form a uniformly lightened slab. This supersedes the earlier feature/selected/action linear recipes in this report. Actual demo recipes and verification are in the implementation receipt; future production phases reuse these lessons without new broad research.
