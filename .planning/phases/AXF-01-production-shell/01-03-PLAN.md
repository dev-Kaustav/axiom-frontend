<planner_findings>
- TanStack Router's default search parser JSON-parses values: `?instrument=` followed by 78 nines became the number 1e+78 in a planner spike, and even `parseSearchWith(identity)` turned `n=12` into a number. The router must use its own URLSearchParams-based parseSearch and stringifySearch so every value stays a string.
- TanStack `Link` active matching is fuzzy and includes search by default; use `activeOptions={{ exact: true, includeSearch: false }}` so /app/exposure?portfolio=x still marks Exposure and an unknown sub-path marks nothing.
- `import.meta.env.DEV` is statically false in `vite build`, so a route list built as `DEV ? [galleryRoute] : []` with a lazy component import drops the gallery chunk from production output.
</planner_findings>
